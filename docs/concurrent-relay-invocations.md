# Relay 调用与控制帧并发

Bridge Agent 0.8.7 修复本地调用串行阻塞 Relay 接收循环的问题。一个慢 Connector 状态查询不再挡住历史读取、事件确认、Ping/Pong 和能力目录刷新。普通服务调用与本地应用调用共享这一机制。

每个 Relay 连接最多执行 64 个调用，结果按完成顺序返回，以原 request ID 关联。达到上限时返回 `AGENT_BUSY`；被拒绝的请求没有执行，也不会自动排队或重试。调用方需要顺序依赖时必须等待前一个请求完成，不能依赖并行发送请求的完成顺序。

调用开始时取得不可变服务目录快照，随即释放目录读锁。刷新目录不会等待已经开始的 HTTP 调用；新调用使用更新后的目录，正在执行的调用继续使用其开始时的绑定和授权上下文。

在途 future 属于单个连接。断线或退出时取消本地等待，不向下一连接转移、重放请求或发送旧结果。外部端点已经开始的操作可能仍然完成，因此不能把连接关闭解释为副作用未发生，更不能自动重试修改操作。

回归测试使用真实本机 WebSocket 和 HTTP 服务，覆盖慢本地调用与快速普通调用并发、事件发送与确认、Ping/Pong、目录更新、两类请求达到并发上限后的拒绝，以及退出和断线不等待慢调用。
