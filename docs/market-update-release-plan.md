# 客户端市场分发与更新

Bridge Agent 0.6.21 将公开市场分发与平台连接配置分开。市场目录和公开版本安装读取 `src-tauri/distribution-config.json` 的 `marketApiBaseUrl`；产品发布配置随客户端版本交付，由通用 URL 校验和路径构造读取。

## 接口合同

- 正式市场目录：`https://api.baijimu.com/api/local-app-market/apps`。
- 公开精确版本：目录路径后追加 `/{appId}/versions/{version}`；继续传递平台、架构及宿主兼容性信息。
- 客户端自更新继续使用 `https://updates.baijimu.com` 的既有更新合同。
- 平台登录和设备授权继续由平台连接配置管理；显式接受未审核版本的环境注册读取保留其原有合同，不在公开市场失败时自动回退。

市场基础服务 1.2.0 对公开精确版本执行与目录一致的可见性约束：应用和版本均须公开、有效。私有、待审、下架和不存在的版本不通过公开 API 分发。

平台 Component `public-openresty` 18.1.1 将正式入口和旧 `/lowcode3/api/local-app-market/apps`、`/lowcode3/api/local-app-registry/apps` 的只读入口统一回源环境登记的 `LOCAL_APP_MARKET_BASE_URL`。旧注册路径仅映射公开版本读取。网关清除调用者身份和凭据，只允许 GET/HEAD。

旧入口用于让已安装客户端恢复目录、安装与升级读取。应在客户端升级覆盖率和旧路径访问日志证明不再需要后，由网关所有者单独安排退役；不能随本次新客户端发布立即删除。

## 用户可见行为

应用页在市场检查失败时显示错误详情与重试入口，不会让已安装版本看起来像已确认的最新版本。CLI 卡片明确显示“已安装版本”。恢复市场后，重试会清除失败提示并重新计算更新。

## 发布与验证

三个发布单元分别通过市场基础服务 Jenkins、网关不可变制品及环境 Agent Operation、Bridge Agent 官方 GitHub Actions 工作流发布。市场新增合同使用独立确认的 MINOR 1.2.0；网关与客户端修复分别为 PATCH 18.1.1、0.6.21。

验证覆盖真实市场公开精确版本、未公开状态隔离、网关路径和凭据边界、客户端错误与重试、独立更新接口以及多平台签名制品。线上市场版本以公开目录为准；本地开发 CLI 版本不能用作市场已发布版本的证据。
