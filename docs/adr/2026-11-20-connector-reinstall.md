# Connector 清单与显式重装

Bridge Agent 0.21.0 的核心与桌面壳均依赖同一个 local-app-contract 6.0.0 发布提交 b629d2a，替换 4.0.0（915e6b9）。用户已批准 6.0.0 自身固定引用的市场 HTTP 合同 3.1.0（2c354a1）进入两个锁文件。设备包由当前清单解析器校验。

0.20.0 的安装记录即使没有附加能力也会写出 remoteCapabilities。用户选择重新安装。普通清单读取拒绝退役字段。用户在目录发起重装时，安装器读取既有记录的来源、应用 ID 和初装时间，校验与新包的来源关系，再替换包并保存新记录。启动时没有迁移。记录损坏或来源不一致时，安装器拒绝覆盖。

## 0.21.1 市场读取与既有安装

2026-11-21 用户确认 Windows 客户端从已发布的 0.20.0 发布至 0.21.1（MINOR），并单独确认核心与桌面壳将 local-app-contract 6.0.0（`b629d2a58db94c98a054ba4e9c70084f8106e022`）替换为 6.0.1（`fa6b44e7ce3cda780ded57e9178a7c045539f6dc`）。其他依赖维持原锁定。0.21.0 的不可变标签保留原提交。

工作区 1347 的真实市场目录同时返回含 `notificationStream` 的新清单和仍带 `publisher`、`remoteCapabilities` 的冻结清单。0.21.0 的共享合同解析器在后者中拒绝 `publisher`，导致整页失败。6.0.1 在共享合同边界读取额外的顶层字段并忽略它们，保留冻结清单原文。

本版本采用相同的本机清单反序列化规则，替代 0.21.0 要求因退役字段而重装的做法。既有记录可直接读取并按原安装来源参与更新检查，读取不改写记录。退役字段不会投影到清单类型，已知字段校验、启动声明和重装来源校验继续生效。验证覆盖读市场目录和精确版本、读取旧安装记录、拒绝其他来源覆盖以及 Windows MSI 原地升级。
