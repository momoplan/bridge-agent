# Linux 客户端 CLI 基线与手动独立升级

用户于 2026-10-19 明确要求提供升级能力，拒绝自动安装更新；本次保留用户点击确认后安装。
用户分别批准内置 CLI `0.92.0 -> 0.121.0` 和 Bridge Agent `0.13.0 -> 0.14.0` MINOR 发布。
Linux 原公开客户端为 `0.11.3`，本次包含 Linux、macOS、Windows 三平台。

## 根因与责任

Bridge 仓库 VERSION/SHA256SUMS 与 GitHub 变量中的来源都固定于 0.92.0。
CLI 的独立发布器已经完成 0.121.0，消费工作区市场返回同一来源的三平台制品。
旧 CLI 仍调用迁移前的 project-service Git 路由。客户端没有自动市场安装步骤，
这是手动更新策略，不是安装失败证据。

详情页在市场读取失败、无法得到 marketApp 时隐藏了检查按钮；手动检查会吞掉读取失败，
仍显示“版本信息已刷新”。修复后保留检查入口，真实失败显示失败，恢复后可以重试。

## 准确依赖范围

唯一依赖变化是客户端消费的 CLI 0.92.0 -> 0.121.0：精确版本、三平台原始 SHA-256、
同一市场 SourceApplication 的冻结版本同步更新。CLI 仍由独立 CLI 发布器拥有，Bridge
不构建 CLI。其他 Rust/npm 包、锁定来源和传递依赖、服务依赖与授权边界均不改变。
选择已完整发布的 0.121.0，避免消费仍未完成市场发布的后继草稿。

内置来源由 `tools/baijimu-cli/SOURCE.json` 版本化管理，与 VERSION/SHA256SUMS 同时审查；
生成的 INSTALL_SOURCE.json 继续供制品打包使用，隐藏的 GitHub 来源变量不再参与发布。
来源记录是所选不可变发行的配置，不是用户授权或运行时凭据。

## 验证与恢复

测试覆盖市场失败时 CLI 详情仍可检查、失败不报成功、恢复后可重试且检查不触发安装。
Linux 官方质量/发布流水线下载并验证旧版与新版真实 ZIP，通过实际托管安装器执行
只读发现、用户安装、失败保留旧版本、重试、重启保持、更高版本不降级及回滚。
测试只用公开制品和已读取的 Owner 合同夹具，不向 CI 复制用户凭据。

发布仍使用精确远程 main 上的不可变 bridge-agent-v0.14.0 标签和唯一 release-bridge-agent
工作流，显式选择 Linux/macOS/Windows。新安装消费新基线；已独立安装更高版本保留。
失败时使用托管 CLI 历史版本与既有客户端发布恢复流程，不移动标签或覆盖不可变制品。
