# 独立交付市场读取路径修复

2026-10-29 当前用户要求将市场路径修复从 Shell 改造和 CLI 捆绑审核中独立拆出、合入和发布，并将真实市场读取纳入客户端发布验收。

已发布客户端的 local-app-contract 4.0.0 解析市场读取合同 4，但请求仍指向返回合同 3 的旧入口。服务端已同时提供旧入口和 `/api/v4/local-app-market/listings`；客户端统一切换市场基址后，列表、精确版本与制品路径沿同一基址构造。不修改共享库依赖、Shell、CLI 捆绑版本或审核状态，不增加格式协商或失败回退。

私有环境安装的冻结版本与制品仍使用 `/api/local-apps`，不能由市场路径替换最后一段来推导。两个基址仅复用消费环境服务的 API 根地址，分别构造自身正式路径；回归测试覆盖根地址、环境前缀和 `/lowcode3` 后缀。

发布质量检查显式执行现有桌面的真实市场测试，复用正式凭据选择、URL 构造、HTTP 解码、目录校验、展示投影及精确版本读取。测试保留普通离线测试的显式忽略标记；发布器必须使用 `--ignored --exact` 执行它。执行失败、缺少验收身份、空目录、精确版本不一致或实际执行零个测试均阻止签名和构建发布制品。回执只记录准确源码提交、合同版本、目录与版本条数，不保存凭据或原始响应。

GitHub Secret `BRIDGE_AGENT_MARKET_ACCESS_JSON` 提供验收身份，格式为 `{baseUrl, environmentKey, workspaceId, token}`。地址、环境、工作区和凭据均由授权配置提供，代码无具体环境和工作区默认值。验收只执行列表与精确版本 GET，不安装应用或修改工作区；验收身份与 CLI 捆绑来源的离线校验各自独立。Secret 不注入普通 PR、编译或签名步骤，也不进入构建制品。

本次独立交付不消费 `codex/shell-execution-bridge` 的其他改动。该分支保留，后续任务在最新主线变基时处理已独立交付的路径修复。客户端版本和实际发布证据以最终不可变标签、准确提交及发布流水线为准。
