# 查询与进程生命周期

`load_config` 只读取现有配置和凭据，不写文件、不导入明文 token、不补默认服务、不修权限。缺少配置或未完成升级的配置直接报告错误。`initialize_config` 是启动和显式安装/配置操作的准备入口，分别执行缺失配置创建与 `migrate_config`。开发凭据权限修复也只在初始化执行；写凭据时保证私有权限。

Shell、宿主前台应用和同步命令共享进程树所有权：Unix 创建独立进程组，Windows 暂停创建后分配到 Job，再恢复主线程。超时或取消终止本次任务的进程树。Shell 输出单流最多保存 16 MiB，并标注截断；退出后的管道收集最多等待 2 秒，stdin/输出任务随调用释放。同步命令使用临时文件收集输出，避免后代继承管道导致 EOF 永不出现。正常退出也清理后代；只有明确允许 daemonize 的旧式生命周期启动器在成功后解除所有权。

宿主进程表只在确认退出后删除记录。停止请求先短锁复制接收器，再在锁外运行停止命令并等待；等待超时不代表进程已停止，后台监督继续负责回收。管理请求的生命周期读门禁保留，防止调用与升级、卸载交叉；它不串行化普通管理查询。

Python 探测单进程上限 3 秒、候选探测预算 10 秒，虚拟环境创建 180 秒、依赖安装单次 600 秒。包进程枚举 5 秒、外部停止命令 10 秒；生命周期脚本按声明的 timeoutSecs 执行，默认 20 秒。终止后的退出确认另有 2 秒上限。

管理 HTTP 只直连本机且不跟随重定向。响应在读取每个分块时校验 4 MiB 上限，应用错误 code/data 经过桌面与 iframe 两层传递。连接失败、超时、响应过大分别返回明确错误码；客户端超时不等于服务端操作被取消，写操作不自动重试。

回归测试覆盖只读配置不写盘、父进程退出/取消/超时后后代不能继续写入、继承输出管道不阻塞完成、应用错误透传、无 Content-Length 响应大小上限。进程所有权 helper 的跨平台测试应在原生 Windows CI 上执行；交叉类型检查不能代替 Windows Job 的运行验证。
